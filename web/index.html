Payment security model

Payment intents are validated locally, persisted in SQLite with unique idempotency constraints, and bound to exactly one PayPal Sandbox order. The browser never marks a payment as paid. Capture is confirmed only through PayPal's capture API followed by an authoritative order lookup. Webhooks must pass PayPal signature verification and reconciliation against the same authoritative order.

Envelope and protocol compatibility

Payments use versioned hybrid envelopes: ML-KEM-768 encapsulation → HKDF-SHA-256 with SHA-256 context binding → AES-256-GCM. Each envelope names its algorithm, key ID and version. ML-DSA-65 signs authorizations and evidence. This protects merchant payment data and records under merchant control. It does not claim to secure PayPal's internal infrastructure or to make the PayPal HTTPS API post-quantum.
